Recommendations in Current Session:
- Allow players to configure what defines Push, Accuracy, Consistency, and Deficit through the settings.
- The system should work similarly to how players configure RICE / LN / FLN, by adjusting percentages to control the recommendations.
- For example, Push recommendations should not exceed the 90–95% clear-rate range. Recommended maps should be around the same difficulty level as the player's top X best clears.
- It makes no sense to recommend maps that are significantly above the player's current skill level.

Jobs:
- Implement a caching system for difficulty calculations and pattern analysis, similar to the existing caching system used for certain searches in Download.
- As the administrator, I should be able to share my existing Sunny Dan, Daniel Dan, and Rework Dan calculations, as well as pattern analysis results, through the Hub API.
- Store these results in a cache so other users can benefit from calculations that have already been performed.
- Display calculation progress indicators, similar to those used for downloads. A small toast notification should appear at the bottom of the screen, even when the user navigates to another page.
- The cache system should be version-aware and tied to a specific Roxysu version.
  - I should be able to prepare and upload cached calculations for an upcoming version locally before releasing it.
  - When users update Roxysu, the app should check for new cached calculations and recalculate results when necessary, especially for Rework Dan calculations and pattern analysis.
  - Eventually, I should be able to manually clear caches associated with older difficulty-system versions once no users are relying on them.
- Since Jobs are a core part of the application, the system should be more proactive. Jobs should automatically run after the first sync, potentially after prompting the user with a modal to explain what will be calculated.
