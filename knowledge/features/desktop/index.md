# Desktop

## Purpose

Electron packaging shell that spawns server + realm-reader (and, on NixOS
packages, the bundled In-game overlay host); same architecture as browser
`bun run dev`.

## Business meaning

Distribute Roxysu as a desktop app without changing the local-mirror-centric architecture.

## Important symbols

- `apps/desktop/main.js` — spawns client app + realm-reader + optional overlay host; sets `ROXYSU_DESKTOP=1`, `ROXYSU_PACKAGED=1` when `paths.isPackaged` (Nix / electron-builder; unset for `bun desktop`), and `HUB_URL` (`https://roxysu-api.yonx.app` unless overridden). Any unexpected server exit or spawn `error` while not shutting down goes through the same respawn policy as the realm-reader (`respawnPolicy.js:decideRespawn`, pure, unit-tested: 2 s doubling to 60 s, a run ≥ 60 s resets the counter, give-up after 6 consecutive short-lived runs). A server run's "uptime" is measured from the last successful healthz probe (`serverHealthyAt`), not from `spawn()`: a child that stays alive but never passes `/api/system/healthz` counts as a short-lived failure and cannot reset the respawn budget (desktop D-NEW-2). A respawn gives healthz 60 s (first boot still 180 s) before the child is stopped so its exit drives the next policy round. — a "server stopped" splash status, respawn, `waitForServer` re-run, then a window reload; only an exhausted budget ends the session, through the fatal-error dialog (see "Lifecycle and recovery" below). The realm-reader and overlay host are left running across a server respawn (the overlay self-heals via its poll-failure rule and respawns once settings polls answer again). `REALM_MAX_OLD_SPACE_MB` optionally prepends `--max-old-space-size` to the realm-reader node spawn (opt-in heap guardrail; unset = no flag). `watchOverlayHostSetting` polls the client-app settings store and spawns/restarts/stops the bundled `resources/overlay/roxysu-overlay` on Linux + Wayland per the `overlay.host_enabled` toggle, `overlay.host_url`, and optional `overlay.host_output` (passed as `--output=` only when set); while disabled it stops the child and suppresses the liveness respawn, otherwise respawns the host if it exits on its own (15 s, then doubling to 5 min, parked after 5 quick deaths or at once on exit 78 — see "Lifecycle and recovery"; a changed URL or monitor restarts at once); the apply decision lives in `apps/desktop/overlayApplyPolicy.js` (`decideOverlayApply`, pure, unit-tested; `childIsAlive` treats signal death as dead) and stops a live host after 5 consecutive failed settings polls regardless of the last known toggle (see in-game-overlay rule 14). Poll runs are serialized through `apps/desktop/overlayApplyLoop.js` (`createApplyGate` allows one run in flight and coalesces mid-flight ticks into a single re-run; `executeOverlayDecision` awaits the stop before a replacement spawns, so a restart never overlaps two hosts). The settings fetch (`apps/desktop/overlaySettings.js`) requires HTTP 200 with an `overlay` object and a boolean `enabled`, and caps the body at 64 KiB — a non-200 error document counts as a failed poll, not as "enabled with the default HUD URL". `guardOverlaySettings` re-validates `hostUrl`/`output` with `apps/desktop/overlayUrlGuard.js` (CommonJS mirror of the server parsers) before they reach argv: a rejected URL falls back to the default HUD URL, a rejected monitor follows the osu! window, both logged. The settings UI's "Restart overlay" action bumps a monotonic `overlay.host_restart` nonce, which restarts the host at once (bypassing the liveness gap; the shell records the nonce it spawned under, so one click restarts exactly once). `ROXYSU_OVERLAY_BIN` overrides the binary path. The host runs with a long age backstop (`ROXYSU_OVERLAY_MAX_AGE_SEC`, default 21600 s = 6 h; `0` disables) instead of the old `--watchdog-max-age-sec=0`, while the FD/RSS watchdog caps remain. An unexpected throw in an apply run is logged (`overlay apply failed: …`) and the gate still releases. Quit is held in `before-quit` (`preventDefault()`) until `shutdown()` has stopped every child: SIGTERM, then SIGKILL after 5 s, then give up 2 s later if `exit` never arrives, then `app.quit()` again. This matters because the server and realm-reader only handle SIGTERM cooperatively (realm-reader checks its flag between syncs), so a bare SIGTERM could leave them holding `ROXYSU_PORT` after Electron exited. Preload bridge (`roxysuDesktop`): `openExternal`, `writeClipboardImage` (PNG bytes via `clipboard.writeImage` for session share cards, rejected above 15 MB). The window stays on the app origin (`http://ROXYSU_HOST:ROXYSU_PORT`): `will-navigate` / `will-redirect` block anything else, `setWindowOpenHandler` denies new windows, and `http:` / `https:` / `osu:` are handed to `shell.openExternal` so an osu! client link or a website link cannot blank the window or inherit the preload. Both IPC handlers reject a sender whose frame URL is not that origin. `waitForServer` (`apps/desktop/waitForServer.js`) treats the child as up only for HTTP 200 with JSON `{ ok: true, service: "roxysu-server", instance: <this launch's token> }` on `/api/system/healthz`, one probe at a time, and aborts when shutdown starts; the service marker keeps a stray process on the port from satisfying the wait. `desktop.log` and each child log are capped at 10 MiB with one `.1` backup (`apps/desktop/logRotation.js`; desktop.log is size-checked at most every 30 s, child logs on (re)open and every 15 s while the child runs, by copy-truncate of the shared append fd). The renderer sets `sandbox: true` (plus `contextIsolation: true`, `nodeIntegration: false`); the preload only needs `contextBridge`/`ipcRenderer`. Windows/Linux have no application menu (shortcuts come from `shellShortcuts.js` instead); macOS gets a minimal standard menu. The pre-paint language/overlay/theme bootstrap is `apps/server/public/boot.js`, loaded blocking from `index.html`, so a strict CSP needs no inline-script exception. The Node/Electron static server (`createApp.ts`) sends `Content-Security-Policy` (`script-src 'self'`; Google Fonts, `data:`/`blob:` images/media, loopback + https connect), `X-Content-Type-Options: nosniff`, and `Referrer-Policy: no-referrer` on HTML/assets/SPA fallback. The Win32 launcher forwards its `cmdLine` tail to `RoxysuApp.exe`. A failed `loadURL` ends with the fatal-error dialog unless shutdown is already in progress. A server exit while not shutting down respawns with backoff (policy above).
- Windows auto-update (`auto-update.js`, `autoUpdatePolicy.js`, DD-11 / DD-22): NSIS only. Restart awaits `shutdown()` before `quitAndInstall` so children release `node.exe` and native addons. Download progress logs in 10% steps. A re-check runs every 6 h on an `unref`'d timer. The dialog is parented to the focused window. No NSIS kill macro.
- Quit sequence (`main.js`: `before-quit` → `shutdown()` → `stopChild()` in `apps/desktop/stopChild.js`): `before-quit` calls `preventDefault()`, closes each child's stdin (lifeline EOF) and on POSIX also SIGTERMs the overlay host, realm-reader and server in parallel, waits for each `exit` (SIGKILL after `CHILD_STOP_GRACE_MS` = 5 s). If `kill()` returns false, or the child still has not exited 2 s after SIGKILL, the wait resolves anyway so Quit cannot hang. Shutdown then closes the child log fds, and `before-quit` re-issues `app.quit()` from `finally`. A `quitAfterShutdown` flag lets the second `before-quit` through, so `autoUpdater.quitAndInstall` keeps working. The server and realm-reader install cooperative SIGTERM handlers, so a bare SIGTERM without waiting could leave them alive after Electron exited and holding `ROXYSU_PORT`. The server's SIGTERM handler awaits background writers for up to 3 s (`shutdownBackgroundWork()`) before closing the local mirror, which fits inside the 5 s `CHILD_STOP_GRACE_MS`. On Windows `SIGTERM` is an immediate terminate, so `stopChild` skips it there and relies on the stdin EOF for a graceful stop, with the grace-period kill as backstop (unverified on Windows)
- Realm-reader respawn (`main.js`: `spawnRealmReader` → `scheduleRealmRespawn`): an exit while not shutting down, a spawn `error` (no `exit`), or a failed extract / missing entry reschedules the reader after an exponential backoff chosen by `apps/desktop/respawnPolicy.js:decideRespawn()` (pure, unit-tested): 2 s doubling to 60 s; a run that stayed up at least 60 s resets the consecutive-failure counter; after 6 consecutive shorter runs the shell gives up (logged; restart Roxysu to retry). `spawnRealmReader` returns a Promise of `"running" | "failed" | "spawned"`; only `"failed"` reschedules, and a still-running child (`childIsAlive`) does not. The first packaged extract (`paths.js:ensureRealmExtracted`) uses async `execFile` so `tar` does not freeze the window; the marker is written only after the entry exists, and a quit during extract does not spawn. The failure counter advances only inside `scheduleRealmRespawn`. The pending timer is cleared in `shutdown()`, so a quit never races a respawn. The reader opens the local mirror without migrating and exits on a 60 s schema wait, which the respawn also covers. No UI indicator exists for a given-up reader; the desktop log is the only surface
- `apps/desktop/preload.js` — `contextBridge.exposeInMainWorld("roxysuDesktop", …)`: `openExternal`, `writeClipboardImage`, `onServerState(cb)` (returns unsubscribe). `writeClipboardImage` accepts only a Buffer, ArrayBuffer, or Uint8Array (`clipboardImage.js:toImageBuffer`); the 15 MB cap is checked before any wrap, and array-likes are rejected (DD-17)
- **Lifecycle and recovery** (desktop deep dive DD-1…DD-10):
  - *Parent lifeline (DD-1).* Server, realm-reader and overlay are spawned with stdin as a pipe. Node children get `ROXYSU_PARENT_LIFELINE=1` and run `attachParentLifeline` (`parentLifeline.ts`): stdin EOF/close → graceful `shutdown("parent-exit")`. The overlay gets `--exit-on-stdin-eof` (`lifecycle.rs:watch_stdin_eof`). EOF happens on every kind of parent death, SIGKILL included, so no orphans keep port 4321.
  - *Own server only (DD-2).* Each launch generates `ROXYSU_INSTANCE_TOKEN`; healthz echoes it with the pid, and `waitForServer({ expectInstance })` ignores a server from another launch. The server exits `98` (`EXIT_ADDR_IN_USE`) when the port is taken; the shell never respawns 98 and goes straight to the fatal dialog. Stuck-lock clearing runs only after the socket is bound.
  - *Fatal dialog (DD-3).* `failFatal(reason)` (port-in-use, respawn-exhausted, health-timeout, load-failed, ui-missing, renderer-crash-loop) shows an error dialog with the reason, the port owner (`probePortOwner`: older Roxysu server + pid, or another program), the last server.log lines and the logs path; buttons Open logs folder / Retry (`app.relaunch`) / Quit. Wording in `fatalReport.js`.
  - *Overlay crash loop (DD-10, DD-10b).* `decideOverlayApply` backs off liveness respawns (15 s doubling to 5 min), parks after 5 deaths shorter than 60 s, and parks at once on exit 78 (`UNSUPPORTED_EXIT_CODE`: no Wayland / no wlr-layer-shell). Toggle, URL, monitor or the Restart nonce un-park. A park writes `{state, reason, at}` to `overlay-host-status.json` in the data dir (`unsupported` or `crash-loop`). Turning the overlay off clears that file even when there is no child to stop (`overlayHostStatusWrite`). A failed settings poll, including the poll-failures stop, does not. A launch that will not run the watcher (not Linux+Wayland, or no overlay binary) writes `running` so a previous park does not stick. The park line is also a banner on every page in the desktop shell, not only Settings → Setup. The client app serves it as `GET /api/overlay/host-status` (missing file → `absent`). Settings shows the parked line in the In-game overlay section.
  - *Overlay library path (DD-21).* `overlayEnv` drops `LD_LIBRARY_PATH` when `ROXYSU_RESOURCES` is set, unless `ROXYSU_OVERLAY_LIBRARY_PATH` names the path the host should see. WebKitGTK then uses its own RUNPATH instead of the Nix wrapper's libstdc++ / icu / openssl.
  - *Second launch (DD-20).* `second-instance` shows the window, flashes the frame, then focuses. A launch before the window exists is kept and revealed when the splash is created. The flash stops on focus, or after 5 s if focus never arrives, so it cannot run forever. Electron userData is not moved when `ROXYSU_DATA_DIR` is set.
  - *Missing cwd (DD-23).* `spawnNodeEntry` logs `cwd missing: …` and emits that error instead of a misleading `spawn …/electron ENOENT`.
  - *Overlay poll (DD-14).* The shell polls `GET /api/overlay/host-config` (`{enabled, hostUrl, output, restartAt}`, weak ETag stored only after a parsed 200, 304 reuses the last good body and a 304 with no cache is a failed poll) instead of the full settings document. `overlaySettingsPollMs` is 4 s while the host is enabled or unknown, 10 s while it is known disabled.
  - *Server restarts in the UI (DD-6).* On a scheduled respawn the shell sends `{ state: "restarting", attempt, maxAttempts, delayMs }` on `roxysu:server-state` to app-origin pages; `DesktopServerBanner` shows it (i18n `app.desktop.*`). Recovery reloads in place (route kept) via `reloadKeepingRoute`.
  - *Renderer recovery (DD-7).* `render-process-gone` reloads (route kept) up to 3 crashes per minute, then the fatal dialog; `unresponsive` asks Wait / Reload.
  - *One startup (DD-12).* The first `waitForServer` carries a `waitId`. A newer wait aborts the previous `startupAbort` before replacing it. `finishStartup` (`startupOnce.js:createStartupJoin`) is the only path that does `loadURL` → realm-reader → overlay host → updater. A respawn that arrives while that work is still in flight shares the promise and does not also reload. If `loadURL` fails while a respawn is pending or has taken over the wait, that failure does not open the fatal dialog. The shell yields one turn first so the child exit handler can schedule the respawn. The respawn reloads. After startup settles, a later respawn reloads. `serverHealthyAt` is set only while `childIsAlive(serverChild)`.
  - *Health poll and clocks (DD-13, DD-25).* `waitForServer` retries every 50 ms for the first 5 s, then 250 ms. Timeouts and the server, realm-reader, and overlay uptime / health stamps use `performance.now()`. `Date.now()` stays on log lines and the window-ready marker.
  - *URL logs (DD-18).* `urlPolicy.js:redactUrlForLog` keeps origin + pathname only (`file:` is `file:` + pathname; unparseable input is `[invalid-url]`). `openExternal`, `loadURL`, splash fail-load, rejected overlay host URLs, and the overlay spawn argv log go through it so OAuth `state`, tokens, and search terms never land in `desktop.log`.
  - *HTTP cache and spellcheck (DD-15, DD-16).* The cache wipe token is `CACHE_EPOCH` only, not `version:epoch`, so an update does not clear the HTTP cache. Bump `CACHE_EPOCH` when a fix needs another wipe. `webPreferences.spellcheck` is false.
  - *Splash (DD-19, DD-24).* `#status` is `role="status"` / `aria-live="polite"`. `splashLocale.js` picks en/fr/es/pt from `app.getLocale()` for Starting / Waiting for server / Opening Home / Server stopped — restarting, and `setSplashStatus` sets `<html lang>`. Buttons and links are no-drag. The window-ready marker is written once per start. Unreferenced `apps/desktop/index.html` and `renderer.js` are gone.
  - *Window state and shortcuts (DD-8, DD-9).* `window-state.json` in userData keeps normal bounds, maximized and zoom (sanitized by `windowState.js`: min 960×600, off-screen positions dropped). Ctrl/Cmd +/−/0 zoom (persisted), Ctrl+R/F5 reload, F11 fullscreen, F12 dev tools (unpackaged only) via `before-input-event`.
- `apps/server/src/shared/upgradeSocketGuard.ts` — `guardUpgradeSocketErrors()` attaches a socket `error` listener to every HTTP **upgrade** socket on the Node server (armed from the `app.listen` callback in `index.node.ts`). Required because `@elysiajs/node` always installs a crossws upgrade handler even with no `.ws()` routes: a rejected handshake is answered by writing a normal HTTP body onto the raw upgrade socket, and crossws' `sendResponse` never listens for `error`, so a client that hangs up mid-response raises an unhandled `EPIPE`/`ECONNRESET` and kills the Node process (which the desktop shell then respawns with backoff — see the `main.js` respawn policy above). Upstream crossws is still unfixed — keep this guard, and do not patch `node_modules`. Bun (`src/index.ts`) is unaffected; it does not use the Node adapter
- The server child is spawned with `NODE_OPTIONS=--expose-gc` (merged with any inherited value). Backfill jobs need a forced collector between maps so note graphs do not accumulate; Node only exposes `global.gc` with that flag, and `NODE_OPTIONS` is the only channel that also reaches dev `tsx`, since `spawnNodeEntry` drops positional node args on the `tsx` path. Scope it to the server child — Electron itself must not inherit the flag. The same spawn path also explains why the server inherits a **~4 GB** default V8 heap on Node, which is why backfill jobs check heap ratio and not just free RAM (see [rework-dan-recommendations/](../rework-dan-recommendations/index.md) rules 11–13). When `ROXYSU_LIBRARY_PATH` is set, `spawnNodeEntry` replaces the child's `LD_LIBRARY_PATH` with that value so Node does not load Chromium libraries from the Electron wrapper
- `nix/prebuilt.nix` / `nix/package.nix` — bundle the In-game overlay host from [nix/overlay-rs.nix](../../nix/overlay-rs.nix), set `--set-default HUB_URL https://roxysu-api.yonx.app`, and set `ROXYSU_NODE_BIN` plus `ROXYSU_LIBRARY_PATH` (libstdc++, zlib, openssl, icu). The prebuilt package launches nixpkgs Node 22 (`NODE_MODULE_VERSION` 127, matching the CI tarball's natives). `resources/node/node` is the nodejs.org binary and is not executed: `autoPatchelf` would move its embedded V8 snapshot and the process SIGSEGVs at startup. The install asserts `resources/node/VERSION` is `22.*`. The from-source package still launches nixpkgs Node 24 and rebuilds natives against it
- `publish.sh` — bumps versions, tags to trigger CI, builds and uploads
  `RoxysuPreview.zip` (standalone Tosu counter) to the GitHub release, pins
  `linux-resources` to the versioned GitHub tarball, then force-moves the tag
  to that lock commit

## Business rules

1. The desktop shell uses the newest Electron major nixpkgs still allows (`meta.knownVulnerabilities` empty). Electron 42 is end-of-life and Nix refuses to evaluate it. Windows installers bundle the same major from `apps/desktop` `electron` via electron-builder. Child processes use a Node runtime, not Electron's Node: Windows uses `resources/node`, Nix prebuilt uses nixpkgs Node 22 via `ROXYSU_NODE_BIN`, Nix from-source uses nixpkgs Node 24 via `ROXYSU_NODE_BIN`.
